# 工具失败后的恢复流程

## 铁律

**同一组参数不要重试第二次。** 报错说明前提错了，重试只会浪费预算。

## 按错误类型分派

| 错误信息里出现 | 真实原因 | 正确动作 |
|---|---|---|
| `文件不存在` | 路径写错，或文件名记错 | 用 `list_dir` 看当前目录真实有什么，再拼路径 |
| `是目录` | 把目录当文件读 | 换成 `list_dir` |
| `越出了工作区` | 用了绝对路径或 `..` | 改成工作区内的相对路径 |
| `参数校验未通过` | 类型错或缺必填 | 照错误里写的类型重新传，整数不要加引号 |
| `不是合法 JSON` | 参数被截断了 | 简化参数，一次只填必要字段 |
| `需要 write 权限` | 运行时没开写权限 | 不要绕，直接在答案里说明需要写权限 |

## 连续两次同类失败

停止试错，把已经确认的事实整理成答案返回，并明确写出：

> 未能完成的部分：X。原因：Y。已验证的事实：Z。

这比继续撞墙有价值——运行时会把连续失败记成指标，蛮干会拉低整条流水线的分。
