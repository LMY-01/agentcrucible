## 权衡数字

| 指标 | 160 基线 | 80 预算 | 变化 |
|---|---:|---:|---:|
| 质量分中位数 | **0.953** | **0.912** | **-0.041** |
| 质量分区间 | [0.931, 0.954] | [0.898, 0.934] | 有重叠 |
| 通过率中位数 | **90%** | **80%** | **-10 个百分点** |
| 通过率区间 | [85%, 90%] | [80%, 85%] | 在 85% 处重叠 |
| pooled token 中位数 | 54,161.5 | 50,569 | **-6.63%** |
| pooled token 均值 | 62,663 | 58,416 | **-6.78%** |
| 三轮总 token | 3,759,776 | 3,504,938 | **-254,838** |

折算：**每节省 10% token，约损失 15.1 个百分点通过率**。这是按本轮中位数变化计算的经验比值，不是可外推的线性定律。

## 结论与理由

1. 80 字只带来约 6.6% 的 token 中位数收益，没有达到值得牺牲检索导航能力的幅度。
2. 通过率中位数下降 10 个百分点；质量分中位数下降 0.041。虽然质量分区间重叠，不能宣称显著回退，但也无法证明质量不受影响。
3. 因此不把 80 字配置设为默认，不继续为了分数反复试其他摘要长度。
4. `KB_SEARCH_SUMMARY_CHARS` 保留为可配置实验入口，默认仍为 160；生产行为不变。
5. 本次最有价值的结论是：**工具结果虽然是最大 token 桶，但不能只凭占比砍内容；压缩检索摘要带来的少量收益可能不足以覆盖定位证据的成本。**
