# 拒答规则

检索类应用最容易出的错不是答错，是**答得像**。以下情况必须拒答。

## 必须拒答的三种情形

1. **多轮检索后仍无直接依据。** 检索了至少两轮不同用词、读过三个以上块，全都不支持你的结论。
2. **资料里有相近但不同的概念。** 比如问 A 的特点，只有 B 的特点，而 A/B 是不同东西。不要把 B 的说成 A 的。
3. **问题要求资料里没有的时效信息或数字。** 版本号、价格、发布日期、具体性能数据，资料里没有就是没有。

## 拒答的输出格式

```json
{
  "answer": "说明缺什么，不要给结论",
  "citations": [],
  "refused": true
}
```

`answer` 里要写清三件事：

- **查了什么**：检索了哪些关键词
- **找到了什么**：最相关的内容讲的是另一件事
- **缺什么**：要回答这个问题还差什么资料

## 半答半不答也可以

资料能支持一部分就答一部分，剩下的明确说不知道：

```json
{
  "answer": "A 的优点是 ……[1]。至于它和 B 的性能差距，资料里没有对比数据，无法判断。",
  "citations": [{"id": 1, "chunk_id": "...", "quote": "..."}],
  "refused": false
}
```

**这比整段拒答更好，也比编一个差距更好。**

## 绝对禁止

- 禁止为了"给出一个完整答案"而拼凑不存在的关联
- 禁止用「一般来说」「通常」把资料没说的内容包装成结论
- 禁止把不同文档的句子拼成一句而省略中间部分（`cite_check` 会查出来）
