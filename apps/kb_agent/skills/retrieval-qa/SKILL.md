# 检索问答

## 这份语料的检索经验（不是通用常识）

1. **标题就是问题。** 这批资料是面试问答集，每个小节的标题本身就是一个问句。
   用 `mode="bm25"` 搜标题里的原词（比如「PagedAttention」「HYDE」），命中率高于 hybrid。
   口语化的问法先转换成资料里的术语再搜。

2. **一个概念常散落在多篇文档里。** 例如 PagedAttention 在 vllm readme 和 inference_optimize
   里都讲过。第一次检索结果里出现多个文档时，**每个文档各读一块再比较**，不要只读排名第一的——
   实测按后者做会漏掉更权威的那份。

3. **相关度低于 0.03 基本不相关。** 不要为了凑够依据硬用，那会把答案带偏。

4. **摘要只是索引，不是证据。** 摘要是我截断过的，原文里没有这句话。任何写进 citations 的
   quote 都必须来自 `kb_read` 的全文输出。

## cite_check 纪律（最容易违反，代价最高）

**提交前，对 citations 数组里的每一条都跑 cite_check，包括最后补充的那些。**

实测事故：某次任务调了 8 次 `cite_check` 全部通过，但最终提交了 10 条引用——
多出的 2 条从没检查过，而且是编的。交付门禁现在会拦住它，但被拦一次要多花一整轮时间和 token。

正确顺序：**先把 citations 数组定稿 → 逐条 cite_check → 一次提交**。
不要边提交边补，补的那部分最容易编。

## 流程

1. **先检索，再读全文，最后才回答。**
   `kb_search` 只给摘要，摘要看着像答案也要 `kb_read` 确认——摘要截断处常常漏掉关键限定条件（"通常"、"除…之外"、"仅当"）。

2. **一次不够就换词再检索。**
   检索结果相关度前三条都低于 0.01，或者摘要都在讲别的东西，说明用词不对。
   换文档里的术语重试，不要用大白话硬扛。

3. **同一问题拆成子问题分别检索。**
   "A 和 B 有什么区别"要分别检索 A 和 B，再对比。只检索一次很容易只拿到一半。

4. **每条结论都要挂引用，引用必须逐字。**
   写完引文先跑 `cite_check`，未命中就回 `kb_read` 复制原句。

## 交付方式

**只能通过 `submit_answer` 工具交答案**，不要直接输出文本。工具会校验参数，缺字段会被打回。

三个参数：

- `answer`：结论正文，分点写，每个分点后面用 [1][2] 标出处
- `citations`：`[{"chunk_id": "...", "quote": "原文逐字片段"}]`，quote 必须从 `kb_read` 的输出里复制
- `refused`：资料不足时为 `true`

被打回（参数校验失败）时，读错误信息补齐字段再提交一次，不要改用直接输出文本。

## 禁止

- 禁止用 `kb_search` 的摘要当引文——摘要是我截断过的，原文里没有这句话。
- 禁止凭已有知识补全文档没写的内容。
- 禁止一条引用都不给就下结论。

## 什么情况停下来

翻两次检索、读了三四个块仍然找不到直接依据 → 不要硬凑，加载 `refusal-policy` 并按它的规则作答。
